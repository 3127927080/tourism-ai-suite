## 奖励函数设计（核心需求）

总奖励 = 1.0×正确性 + 0.5×格式 + 0.4×过程 + 0.3×长度 + 0.2×风格多样性（权重体现"正确性最高、格式适中、其余辅助"）。每个 episode 存 `reward_info` 分量字典，逐步记录到 TensorBoard。

**1. format_reward(response) ∈ [-0.5, 0.5]** — 权重 0.5
- `parse_triples` 完全合规（全部行可解析为 `(a, b, c)`、无多余文本、无畸形括号）→ 0.5
- 部分行合法 → 0.5 × 合法行比例
- 完全不可解析 → **-0.5 强惩罚**（注释说明：用户要求"负无穷"式硬约束，但组内标准化对极端值会出 NaN，故用大幅负值替代）

**2. correctness_reward(response, gold) ∈ [0, 1]** — 权重 1.0（最高）
- 精确匹配（规范化三元组集合相等且格式合法）→ 1.0
- 否则连续分：`0.5×triple_f1 + 0.3×entity_f1 + 0.2×relation_f1`
  - triple_f1：三元组集合 micro-F1（主信号）；entity_f1：头∪尾实体集合 F1；relation_f1：关系集合 F1
  - 典型落点 0.3~0.8，满足"模糊/语义匹配给连续奖励"；"实体对但关系错"≈0.4，满足部分正确要求
  - 幻觉三元组拉低 precision 从而扣分
- 解析失败 → 0

**3. process_reward(response, sentence) ∈ [0, 0.3]** — 权重 0.4（过程/步骤奖励，确定性 PRM 替代）
- 把每条预测三元组视为一个"中间步骤"：头、尾实体（NFKC 规范化后）都在原句中做子串匹配（落地性检查）→ 该步正确
- reward = 0.3 × 落地步骤数 / 预测总步数；监督"实体抽取"这一前置步骤，抑制幻觉实体

**4. length_reward(response, gold, is_exact) ∈ [-0.1, 0.5]** — 权重 0.3（仅正确时激活主体分）
- 精确匹配：len(response) ≤ 1.2×len(gold) → +0.5（简洁偏好）；超出则 0.5×(1.2×len(gold)/len(response)) 递减
- 非精确匹配 → 0；但字符数超长（>400，对应明显截断/啰嗦）→ -0.1 防刷长度

**5. style_diversity_reward(response, group_responses) ∈ [-0.2, 0.2]** — 权重 0.2
- 重复惩罚：字符 3-gram 重复率 rep = 1 − unique/total → −0.2×rep
- 组内多样性：与同 prompt 其余 7 个候选的平均字符 3-gram Jaccard **距离** → +0.2×均值（激励探索不同抽取路径；评估单条时该分量为 0）

## 训练循环细节

- **Episode 数据类**：example_index / prompt_ids / response_ids（截断到首个 EOS 含 EOS）/ old_log_probs / response_text / reward / reward_info
- **rollout**：每步取 8 个 prompt；同 prompt 的 G=8 条一次性 `policy.generate(input_ids.repeat(8,1), do_sample=True, temperature=1.0, top_p=1.0, output_scores=True, return_dict_in_generate=True, max_new_tokens=128)`——同组 prompt 完全相同故无需 padding，天然批量化；old_log_probs 从 generate 返回的 scores 用 log_softmax+gather 提取（与 text2sql 做法一致）；每条按首个 EOS 截断
- **优势标准化**：组内 `(r − mean) / (std + 1e-4)`（DeepSeek-R1 式）
- **update_policy**：全部 episode 按长度排序切 micro_batch=8；前向算 new_log_probs，`ratio = exp(new − old)`，PPO 裁剪 `min(ratio·A, clamp(ratio,1±ε)·A)`；KL 用 k3 估计 `exp(Δ)−Δ−1`（Δ = ref_lp − new_lp，ref 通过 `with torch.no_grad(), policy.disable_adapter()` 取合并 SFT 后的基座，零额外显存）；梯度累积跨 micro-batch，clip_grad_norm 1.0，AdamW(lr=1e-5, betas=(0.9,0.999), weight_decay=0)
- **evaluate**：每 50 步在 dev 前 100 条做贪心生成（group_size=1, do_sample=False），按 eval_triples.py 同公式算 exact_match 与 micro P/R/F1，写 TensorBoard
- **超参数常量**：GROUP_SIZE=8，PROMPTS_PER_STEP=8（64 episodes/步），MAX_STEPS=500（10096 条 ≈1262 步/epoch，500 步约 0.4 epoch，可按需调大），MICRO_BATCH_SIZE=8，CLIP_EPSILON=0.2，KL_COEF=0.02，MAX_NEW_TOKENS=128，LR=1e-5，SEED=42；CUDA 可用则 bf16 否则 fp32，update 期间 use_cache=False + gradient_checkpointing(use_reentrant=False)
- **输出**：LoRA adapter 存 `./finetuned/03_grpo_lora_demo`（每 100 步另存 checkpoint 到 `./finetuned/03_grpo_dir_demo/checkpoint-XXX`）；TensorBoard 写 `./logs/03_grpo_dir_demo`（中文标签：损失/平均奖励/各奖励分量/kl/梯度范数/评估指标）；训练报告 JSON（超参 + 每步指标历史 + 最终评估）写 `./data/grpo_training_report.json`

## 验证方式
1. 先单独跑奖励函数自测：临时用几条样例（精确匹配 / 实体对关系错 / 幻觉实体 / 格式错误 / 重复啰嗦）检查各分量分数符合设计区间
2. 把 MAX_STEPS 临时改为 2、评估子集改小做端到端冒烟运行，确认 rollout→奖励→更新→保存→报告全链路无报错
3. 恢复 MAX_STEPS=500 交付；训练本身耗时较长，由你择机启动完整训练
