## 2. 现状：仍是课程「电商客服」前端

.env 当前变量（两个应用相同）：

```dotenv
VITE_CUSTOMER_SERVICE_URL=http://127.0.0.1:8000
VITE_ECOMMERCE_SERVICE_URL=http://192.168.200.188:8001
VITE_AI_SERVICE_URL=http://127.0.0.1:8002
```

`src/api.js` 中 `commerceApi` 仍指向电商接口（`ECOMMERCE_SERVICE_URL`）：

| 前端现有方法 | 现有路径 | 改造后应指向（tourism-service 8001） |
|---|---|---|
| `products` | `GET /api/v1/products` | `GET /api/v1/products?query=&type=`（参数调整） |
| `orders` | `GET /api/v1/orders` | 不变 |
| `order` | `GET /api/v1/orders/{id}` | 不变 |
| `logistics` | `GET /api/v1/orders/{id}/logistics` | **改** `GET /api/v1/orders/{id}/trip` |
| `afterSales` | `GET /api/v1/after-sales?order_id=` | **改** `GET /api/v1/refunds?order_id=`（另有 `/tickets` 列表） |
| `cancel` | `POST /api/v1/orders/{id}/cancel` | 不变（语义 = 取消预订） |
| `updateAddress` | `PATCH /api/v1/orders/{id}/address` `{address}` | **改** `PATCH /api/v1/orders/{id}/travelers` `{traveler_info}` |
| `createAfterSale` | `POST /api/v1/orders/{id}/after-sales` | **改** `POST /api/v1/orders/{id}/refunds` `{kind, reason}` 或 `POST /api/v1/orders/{id}/tickets` `{ticket_type, issue_description}` |

## 3. 改造要点（后续阶段）

1. `.env`：`VITE_ECOMMERCE_SERVICE_URL` → 建议改名 `VITE_TOURISM_SERVICE_URL`（体地址仍 `http://192.168.200.188:8001`，本机起服则为 `http://127.0.0.1:8001`）；`api.js` 顶部常量同步。
2. `api.js`：按上表把 `commerceApi` 的 `/logistics`→`/trip`、`/after-sales`→`/refunds`+`/tickets`、`/address`→`/travelers`；写接口沿用 `Idempotency-Key`。
3. `App.vue`（user）：业务词与字段旅游化
   - 商品 → 旅游产品；物流 → 出行信息；售后 → 退款/工单；收货地址 → 出行人。
   - 商品字段 `category`→`type`、`specs`→`attributes`、新增 `city`；订单字段增 `travel_start_date/end_date`，去掉 `address`。
   - 产品类型筛选 `hotel|scenic|ticket|transfer`。
4. `App.vue`（admin）：以工单/会话处理为主，改动较小；核对工单类型与文案。
5. `package.json` name 可改为 `tourism-customer-*-frontend`（可选）。
6. 与后端联调：客服 8000 / tourism 8001 / ai 8002 全起后，验证登录（demo-token）、订单、行程、退款/工单页面。
